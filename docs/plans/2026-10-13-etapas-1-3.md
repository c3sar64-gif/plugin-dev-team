# AR-DEV-TEAM · Plan de implementación, etapas 1 a 3

> **Para quien ejecute el plan:** SUB-SKILL REQUERIDA: usa superpowers:subagent-driven-development (recomendada) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`) para llevar el avance.

**Objetivo:** dejar el plugin `ar-dev-team` instalable, con las cuatro skills de convenciones y los nueve hooks probados.

**Arquitectura:** el repositorio es a la vez plugin y marketplace. Las skills son Markdown con el detalle en `references/`. Los hooks son un despachador en Node que normaliza el evento de Claude Code y lo pasa por reglas puras, una por archivo, cada una con sus pruebas.

**Tecnología:** Markdown, Node 22 o superior (módulos ES, `node:test`, sin dependencias de npm), GitHub Actions.

**Especificación:** `docs/specs/2026-10-13-ar-dev-team-design.md`. Este plan cubre sus etapas 1, 2 y 3. Las etapas 4 a 6 (agentes y flujo) y la 7 (adopción en Molino) tendrán sus propios planes.

## Restricciones globales

- Todo el texto en español. Nombres de código en español del dominio, sin tildes.
- Identificador del plugin y del marketplace: `ar-dev-team`. Repositorio: `c3sar64-gif/plugin-dev-team`.
- Stack que describen las skills: ASP.NET Core (.NET 10) en Onion con DDD, PostgreSQL con migraciones SQL a mano, React + Vite + TypeScript + Tailwind con Material 3, login propio con JWT, xUnit + Testcontainers.
- Las skills no mencionan Next.js, Supabase, Minimal APIs, Prisma, Drizzle, Kysely, Django ni componentes de servidor.
- Paginación: `PagedRequest` / `PagedResult<T>` con la forma `{ items, total, page, pageSize }`, máximo 100.
- Errores de la API: ProblemDetails para 400, 401, 403, 404 y 409.
- Cada `SKILL.md` tiene 150 líneas como máximo. El detalle va en `references/`.
- Hooks sin dependencias de npm y sin scripts de bash. Deben funcionar igual en Windows, macOS y Linux.
- Si el despachador o una regla falla, deja pasar. Un error del hook nunca bloquea.
- Variable de salida de emergencia: `AR_DEV_TEAM_REGLAS_DESACTIVADAS` (nombres separados por coma).
- Commits con Conventional Commits, uno por propósito. No se hace push salvo que el usuario lo pida.
- Ningún archivo se elimina sin aprobación del usuario.

## Decisiones que este plan toma por defecto

El usuario puede vetarlas al revisar el plan.

| # | Decisión | Motivo |
|---|---|---|
| D1 | Tipos de commit permitidos: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`, `style`, `revert` | La skill del master nombra cuatro; estos son el conjunto estándar de Conventional Commits |
| D2 | Nombres de DTO: `Create<X>RequestDto`, `Update<X>RequestDto`, `<X>Dto` | Es la convención de la skill del master |
| D3 | Node 22 o superior para los hooks | Es la versión mínima en que `node --test` acepta patrones glob en todos los sistemas |
| D4 | Versión inicial `0.1.0` | Aún sin agentes ni flujo; `1.0.0` al terminar la etapa 6 |
| D5 | El plugin no nombra la librería de rutas del frontend | Molino no la ha decidido; se define en la E0 del proyecto |

## Puntos de atención de la revisión

1. **Rutas de Windows con `\`.** Las reglas deben aplicar igual que con `/`. Prueba en la tarea 6 y de extremo a extremo en la tarea 10.
2. **Commit con heredoc (Bash) o here-string (PowerShell).** Se valida la primera línea real del mensaje, no el envoltorio. Prueba en la tarea 7.
3. **Edit trae solo un fragmento.** Con `new_string` vacío o ausente ninguna regla lanza error ni bloquea. Prueba en la tarea 10.
4. **Entrada rota, vacía o de una herramienta desconocida.** El despachador termina con código 0. Prueba en la tarea 6.
5. **Archivos que no deben bloquearse por error:** pruebas del frontend (`*.test.tsx`), proyectos de pruebas del backend (`*.Tests/`) y la propia capa HTTP (`shared/api/`). Pruebas en las tareas 8 y 9.

````markdown
# Convenciones de backend

El `CLAUDE.md` y los `docs/` del proyecto mandan sobre esta skill. Antes de escribir código nuevo, lee una funcionalidad existente de punta a punta y copia su forma.

## Capas

```
<Proyecto>.Api ──▶ <Proyecto>.Application ──▶ <Proyecto>.Core
<Proyecto>.Infrastructure ──implementa las interfaces de──▶ Core y Application
```

Hay un solo juego de proyectos. Cada contexto del dominio es una carpeta dentro de cada capa.

## Reglas innegociables

1. **Dependencias hacia el centro.** Core no referencia ningún proyecto ni paquete. Application conoce solo a Core. Infrastructure implementa las interfaces. Api solo llama a los servicios.
2. **Las reglas de negocio viven en Core**, en métodos del agregado. El servicio solo orquesta: carga, llama al método y guarda.
3. **Un agregado se modifica solo por su raíz.** Una operación cambia un solo agregado. Si otro debe cambiar, se entera por un evento de dominio.
4. **Un contexto no usa entidades de otro.** Solo ids, DTOs o eventos.
5. **Una regla rota lanza `DomainException`.** La API la devuelve como HTTP 409 con el mensaje en español.
6. **Controladores delgados.** Llaman al servicio y devuelven el resultado. Sin consultas, validaciones ni mapeos.
7. **Servicios Scoped que devuelven DTOs**, nunca entidades.
8. **Todo listado se pagina** con `PagedRequest` y `PagedResult<T>`: `?page=1&pageSize=20`, máximo 100.
9. **El servidor prohíbe; la interfaz solo oculta.** Cada endpoint lleva `[Authorize(Roles = …)]`. El rol se lee de la base en cada petición. Un rol no reconocido es `GUEST`.
10. **Lo que viene de afuera entra por su adaptador** en `Infrastructure/Adapters`.
11. **Eventos de dominio propios y simples**, sin librerías de mediación.
12. **Sin migraciones de EF.** El esquema cambia con SQL escrito a mano (skill `migraciones-sql`).

## Receta para una funcionalidad

1. Migración SQL (skill `migraciones-sql`).
2. Entidad o agregado en Core, con sus reglas y sus pruebas.
3. DTOs en Application.
4. Interfaz y servicio en Application.
5. Controlador delgado en Api.
6. Registro en el método DI del contexto: `services.Add<Contexto>()`.

## Trampas conocidas

- Usa `timestamptz` con `DateTime` en UTC. Normaliza el `Kind` antes de comparar una fecha leída de la base con una calculada.
- Mapea cada columna de EF explícitamente a snake_case. Una entidad sin mapear usa nombres por convención que no coinciden con el SQL escrito a mano.
- Los nombres de clases, métodos y tablas van en español del dominio, sin tildes: `OrdenFabricacion`, `PesarNucleo()`.
````

````markdown
# Convenciones de frontend

El `CLAUDE.md` y los `docs/` del proyecto mandan sobre esta skill. Antes de escribir código nuevo, lee una feature existente completa y copia su forma.

## Estructura

```
web/src/
├─ app/         rutas y layout; páginas delgadas
├─ features/    una carpeta por feature, con su index.ts
└─ shared/      ui/ (primitivos), api/apiClient.ts, hooks/, lib/, types/

## Reglas innegociables

1. **Dependencias `app → features → shared`.** `shared` nunca importa de `features` ni de `app`.
2. **Una feature se importa solo por su `index.ts`.** `@/features/pedidos` sí; `@/features/pedidos/components/Fila` no.
3. **Nunca `fetch` directo.** Todo pasa por `shared/api/apiClient.ts`, que renueva el token una sola vez (single-flight) y reintenta la petición.
4. **Estado local**, con `useState` o un hook de la feature. Sin store global.
5. **Solo Tailwind**, con primitivos Material 3 en `shared/ui`. Sin otra librería de componentes, sin CSS modules y sin estilos en línea, salvo un valor realmente dinámico.
6. **Tokens, no valores sueltos.** Colores por rol (`primary`, `surface`, `error`…), nunca hex ni valores arbitrarios.
7. **La interfaz solo oculta; el servidor prohíbe.**
8. **Página delgada.** Importa la pantalla desde la feature y la muestra. Sin datos ni lógica.

## Reglas de interfaz

- Un solo botón principal por zona.
- Validar al salir del campo y al enviar, no en cada tecla.
- Diálogos con verbos («Aprobar versión», «Eliminar»), nunca «OK».
- Estados vacíos con una explicación y una acción.
- Botón de envío deshabilitado mientras la petición está en curso.
- Áreas táctiles de 48 × 48 px como mínimo.
- Las fechas se muestran en la zona horaria que define el proyecto.

## Receta para una feature

1. `features/<x>/types.ts`: tipos que reflejan los DTOs del backend.
2. `features/<x>/api.ts`: funciones construidas sobre `apiClient`.
3. `components/` y `hooks/` de la feature.
4. `index.ts`: lo único que otros pueden importar.
5. Página delgada en `app/` que muestra la pantalla exportada.
````

````markdown
# Commits

## Formato

```
<tipo>(<ámbito opcional>): <descripción>
```

La descripción va en minúsculas, en imperativo y sin punto final: `feat(pedidos): agrega el bloqueo al iniciar la echada`.

| Tipo | Cuándo | Versión |
|---|---|---|
| `feat` | Endpoint, componente o pantalla nueva | Menor |
| `fix` | Bug, regresión, consulta o interfaz rota | Parche |
| `refactor`, `perf`, `test`, `build`, `ci`, `style` | Cambia el código sin cambiar lo que ve el usuario | Sin cambio |
| `docs`, `chore` | Documentación, dependencias, tareas de mantenimiento | Sin cambio |
| `revert` | Deshace un commit anterior | Según lo que deshace |
| `feat!`, `fix!` | Rompe compatibilidad | Mayor |

## Reglas

1. **Un commit por propósito, nunca uno por sesión.**
2. **Clasifica antes de preparar.** Separa lo nuevo, lo corregido y lo de mantenimiento en commits distintos.
3. **La migración lleva el mismo tipo que el cambio al que sirve.**

5. **Commit y push solo cuando el usuario lo pide.**
6. **No se saltan las verificaciones** (`--no-verify`).
7. **No se reescribe historia ya publicada.**

## Qué evitar

- Mensajes que no dicen nada: «cambios», «arreglos varios», «wip».
- Un commit gigante con todo lo del día.
- Commits que dejan el proyecto sin compilar.
````

```js
import { existsSync } from 'node:fs';

const DE_ARCHIVO = new Set(['Write', 'Edit', 'MultiEdit']);
const DE_COMANDO = new Set(['Bash', 'PowerShell']);

function contenidoDe(herramienta, datos) {
  if (herramienta === 'Write') return String(datos.content ?? '');
  if (herramienta === 'Edit') return String(datos.new_string ?? '');
  return (datos.edits ?? []).map((edicion) => String(edicion?.new_string ?? '')).join('\n');
}

export function normalizar(entrada, { existe = existsSync } = {}) {
  const herramienta = entrada?.tool_name;
  const datos = entrada?.tool_input ?? {};
  if (DE_COMANDO.has(herramienta)) {
    if (typeof datos.command !== 'string') return null;
    return { tipo: 'comando', herramienta, comando: datos.command };
  }
  if (DE_ARCHIVO.has(herramienta)) {
    if (typeof datos.file_path !== 'string') return null;
    return {
      tipo: 'archivo',
      herramienta,
      ruta: datos.file_path.replaceAll('\\', '/'),
      contenido: contenidoDe(herramienta, datos),
      existe: existe(datos.file_path),
    };
  }
  return null;
}
```

`hooks/motor.mjs`:

```js
import { normalizar } from './evento.mjs';
import { REGLAS } from './reglas/indice.mjs';

export const VARIABLE_DESACTIVAR = 'AR_DEV_TEAM_REGLAS_DESACTIVADAS';

export function evaluar(entrada, { env = process.env, existe, reglas = REGLAS } = {}) {
  const resultado = { bloqueos: [], avisos: [] };
  const evento = normalizar(entrada, existe ? { existe } : undefined);
  if (!evento) return resultado;
  const desactivadas = new Set(
    String(env[VARIABLE_DESACTIVAR] ?? '').split(',').map((nombre) => nombre.trim()).filter(Boolean),
  );
  for (const regla of reglas) {
    if (desactivadas.has(regla.nombre)) continue;
    let detalle = null;
    try {
      detalle = regla.detectar(evento);
    } catch {
      continue;
    }
    if (!detalle) continue;
    (regla.accion === 'bloquear' ? resultado.bloqueos : resultado.avisos).push({ regla, detalle });
  }
  return resultado;
}

export function redactar({ regla, detalle }) {
  const titulo = regla.accion === 'bloquear' ? 'Bloqueado por' : 'Aviso de';
  return [
    `[AR-DEV-TEAM] ${titulo} la regla «${regla.nombre}»`,
    `Qué pasó: ${detalle}`,
    `Por qué: ${regla.porQue}`,
    `Cómo hacerlo: ${regla.comoHacerlo}`,
    `Caso excepcional: ${VARIABLE_DESACTIVAR}=${regla.nombre}`,
  ].join('\n');
}
```

`hooks/reglas/commit-convencional.mjs`:

```js
const ES_COMMIT = /\bgit\b[^|;&\n]*?\bcommit\b/;
const HEREDOC = /<<-?\s*['"]?(\w+)['"]?[^\n]*\r?\n([\s\S]*?)\r?\n\s*\1\b/;
const HERE_STRING = /@(['"])\r?\n([\s\S]*?)\r?\n\1@/;
const ENTRE_COMILLAS = /(?:^|\s)(?:-[a-zA-Z]*m|--message)(?:\s+|=)(['"])([\s\S]*?)\1/;
const FORMATO = /^(feat|fix|chore|docs|refactor|test|perf|build|ci|style|revert)(\([^()\s]+\))?!?: \S/;
const AUTOMATICO = /^(Merge |Revert "|fixup! |squash! )/;

export function extraerMensaje(comando) {
  const cuerpo = HEREDOC.exec(comando)?.[2] ?? HERE_STRING.exec(comando)?.[2] ?? ENTRE_COMILLAS.exec(comando)?.[2];
  if (cuerpo === undefined) return null;
  return cuerpo.split(/\r?\n/).map((linea) => linea.trim()).find((linea) => linea.length > 0) ?? null;
}

export default {
  nombre: 'commit-convencional',
  accion: 'bloquear',
  porQue: 'El tipo del commit define el número de versión y el registro de cambios.',
  comoHacerlo: 'Usa <tipo>(<ámbito opcional>): <descripción>, por ejemplo «feat(pedidos): agrega el bloqueo». Ver la skill commits.',
  detectar(evento) {
    if (evento.tipo !== 'comando') return null;
    const coincidencia = ES_COMMIT.exec(evento.comando);
    if (!coincidencia) return null;
    const mensaje = extraerMensaje(evento.comando.slice(coincidencia.index));
    if (mensaje === null || FORMATO.test(mensaje) || AUTOMATICO.test(mensaje)) return null;
    return `El mensaje «${mensaje}» no sigue Conventional Commits.`;
  },
};
```

```js
const EN_CAPA = /\/([\w.]+)\.(Core|Application|Infrastructure)\/(?:.*\/)?[^/]+\.(cs|csproj)$/;
const PROHIBIDAS = {
  Core: ['Application', 'Infrastructure', 'Api'],

function enProyecto(capa, contenido) {
  if (capa === 'Core' && /<(ProjectReference|PackageReference)\b/.test(contenido)) {
    return 'El proyecto Core no puede referenciar ningún proyecto ni paquete.';
  }
  const haciaAfuera = new RegExp(`<ProjectReference[^>]*\\.(${PROHIBIDAS[capa].join('|')})\\.csproj`);
  const hallada = haciaAfuera.exec(contenido);
  return hallada ? `El proyecto ${capa} no puede referenciar a ${hallada[1]}.` : null;
}

function enCodigo(prefijo, capa, contenido) {
  const using = new RegExp(
    `^\\s*(?:global\\s+)?using\\s+(?:static\\s+)?(?:\\w+\\s*=\\s*)?${escaparRegex(prefijo)}\\.(${PROHIBIDAS[capa].join('|')})\\b`,
    'm',
  );
  const hallado = using.exec(contenido);
  return hallado ? `${capa} no puede usar el espacio de nombres ${prefijo}.${hallado[1]}.` : null;
}
```

```js
import { posix } from 'node:path';

const EN_SRC = /^(.*\/web\/src)\/(.+\.(?:ts|tsx|js|jsx|mjs))$/;
const IMPORTS = /(?:\bfrom\s*|\bimport\s*\(\s*|\bimport\s+|\brequire\(\s*)(['"])([^'"\n]+)\1/g;
const ES_INDICE = /^index(\.(ts|tsx|js|jsx))?$/;

function zona(relativa) {
  const partes = relativa.split('/');
  if (partes[0] === 'features') {
    return { capa: 'features', feature: partes[1] ?? '', interno: partes.slice(2).join('/') };
  }
  return { capa: partes[0] === 'shared' || partes[0] === 'app' ? partes[0] : 'otra' };
}

function destino(especificador, raizSrc, carpeta) {
  if (especificador.startsWith('@/')) return especificador.slice(2);
  if (!especificador.startsWith('.')) return null;
  const absoluta = posix.normalize(posix.join(carpeta, especificador));
  return absoluta.startsWith(`${raizSrc}/`) ? absoluta.slice(raizSrc.length + 1) : null;
}

export default {
  nombre: 'limites-features',
  accion: 'bloquear',
  porQue: 'Las dependencias van app → features → shared, y cada feature expone solo su index.ts. Así el interior de una feature puede cambiar sin romper a las demás.',
  comoHacerlo: 'Exporta lo que necesitas desde el index.ts de la feature dueña e impórtalo como @/features/<feature>. Si es genérico, muévelo a shared.',
  detectar(evento) {
    if (evento.tipo !== 'archivo') return null;
    const coincidencia = EN_SRC.exec(evento.ruta);
    if (!coincidencia) return null;
    const [, raizSrc, relativa] = coincidencia;
    const origen = zona(relativa);
    const carpeta = posix.dirname(evento.ruta);
    for (const [, , especificador] of evento.contenido.matchAll(IMPORTS)) {
      const relativaDestino = destino(especificador, raizSrc, carpeta);
      if (relativaDestino === null) continue;
      const dst = zona(relativaDestino);
      if (origen.capa === 'shared' && (dst.capa === 'features' || dst.capa === 'app')) {
        return `shared importa de ${dst.capa} («${especificador}»).`;
      }
      if (origen.capa === 'features' && dst.capa === 'app') {
        return `La feature ${origen.feature} importa de app («${especificador}»).`;
      }
      const mismaFeature = origen.capa === 'features' && origen.feature === dst.feature;
      if (dst.capa === 'features' && !mismaFeature && dst.interno !== '' && !ES_INDICE.test(dst.interno)) {
        return `Se importa el interior de la feature ${dst.feature} («${especificador}»).`;

    }
    return null;
  },
```
